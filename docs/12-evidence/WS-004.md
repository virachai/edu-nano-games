## Known Limitations / Risks

- The gate validates recorded state and required evidence fields; it cannot verify that an evidence record's prose is factually true, nor that a `DONE` transition was authorized by DWB105. For a `DONE` row it requires corroboration in the evidence record and raises a non-fatal note when the record's `Reviewer:` field still reads `pending`.
- Whole-backlog mode (no task ID) is structural only: it checks row shape, valid states, and that referenced task/evidence paths exist. Rows closed before the evidence convention (`MM-001.1`–`MM-001.4`, `DONE` with `—` in the Evidence column) are reported as non-fatal notes rather than failures, matching the runbook rule against fixing unrelated pre-existing state.
- Running the gate with a task ID on a legacy `DONE` row such as `WS-001` fails its `DONE`-corroboration check, because that evidence record does not use the current template's `**Status:**` / `**Assessment:**` fields. The gate's operating envelope is the task being handed off, not historical rows.
- The blockers/follow-up requirement accepts `## Blocker Record`, `## Follow-Up`, or `## Known Limitations / Risks` as a carrier, so a record written before the current template still satisfies it while a record with none of them fails.
- `SELF-CHECK: PASS` is a gate result only; it is not reviewer approval and does not move a task to `DONE`.
