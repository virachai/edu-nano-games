## Result

`scripts/agent-loop.sh` is now a pure scheduler: every cycle delegates the agent
invocation to `scripts/agent-runner.sh`, which remains the canonical single-cycle
execution primitive owning the per-run lock, the hard per-cycle timeout, and the
agent output log.

Observed outcomes:

- Each cycle runs `bash scripts/agent-runner.sh --log-dir <loop log dir> -- <agent-command> [args...]`
  and the loop waits for it synchronously; the loop no longer captures agent
  output, enforces a timeout, or manages the runner's lock.
- `--interval`, `--duration`, `--start-delay`, `--log-dir`, and the custom
  command after `--` keep their previous meaning.
- Loop logging now records cycle begin/end with the observed runner exit code
  (`CYCLE <n> END runner_exit_code=<code>`) plus one aggregate
  `STOP run_id=... cycles=N failed_cycles=M last_runner_exit_code=K reason=<window_expired|signal> log=<path>`
  line; the loop's own exit status is `0` after a completed window and `143` when
  interrupted.
- A real bounded window was executed end to end (1-minute window): one delegated
  cycle, then window expiry and a `reason=window_expired` STOP line with exit 0.
- Regression coverage for delegation, argument preservation, exit-code
  propagation, and synchronous non-overlap is in
  `tests/agent-loop-runner-validation.test.js`.
- `docs/AGENT_LOOP_RUNBOOK.md` documents the runner-backed architecture and the
  resulting log/lock responsibility split.

## Known Limitations / Risks

- The loop's minimum window is one minute (`--duration` is a positive whole
  minute count), so the regression suite starts a bounded loop and stops it once
  it has observed the behaviour under test, instead of waiting for a full window.
  A complete window-expiry run is verified manually above (exit 0 plus the
  `reason=window_expired` STOP line); the aggregate STOP line is additionally
  asserted as source text in the suite.
- On Windows, stopping a loop kills it without trap delivery (`TerminateProcess`
  semantics), so the interval `sleep` can briefly outlive the loop. The tests
  attach no pipes to the loop for this reason — a pipe held by such an orphan
  stalls `node --test` on stdout EOF.
- The per-cycle time bound remains the runner's `--timeout` default (30 minutes);
  the loop has no timeout flag, so a cycle can finish after the duration window
  expires. The loop only stops starting new cycles at the boundary.
- Individual cycle failures do not change the loop's exit status; they are
  recorded as `runner_exit_code=<n>` and `failed_cycles=<n>` in the log, matching
  the existing rule that a non-zero agent exit code is not by itself a task
  failure.
- `--start-delay` and `--interval` remain whole-minute settings, so neither can
  be exercised end to end inside a short automated test.
