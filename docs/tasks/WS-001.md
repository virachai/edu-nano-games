# WS-001 — Workspace Build / Typecheck / Test Gates

## Status

DONE

## Objective

Integrate `packages/*` into the workspace build, typecheck, and test gates so package-level correctness is exercised through the workspace-level verification path.

## Dependency

- MM-001-R — DONE

## Scope

- Inspect the current workspace/package configuration.
- Define or repair workspace-level build/typecheck/test commands that include the relevant `packages/*` code.
- Ensure existing package tests are reachable from the workspace verification path.
- Keep existing MM-001 behavior and tests passing.
- Document the resulting commands and verification contract.

## Out of Scope

- Schema/version validation.
- CI quality gates.
- Render regression policy.
- Creating the second Math Motion concept.
- Unrelated semantic-engine or recipe refactors.
- Production deployment automation.

## Acceptance Criteria

- [ ] Workspace package configuration explicitly covers the intended `packages/*` packages.
- [ ] Workspace build gate passes.
- [ ] Workspace typecheck gate passes.
- [ ] Workspace test gate passes.
- [ ] Existing test suite remains green.
- [ ] No MM-001 behavior/regression is introduced.
- [ ] Commands are documented in the appropriate workspace documentation/package scripts.
- [ ] Evidence records exact commands, results, and relevant package coverage.
- [ ] Working tree is clean after the implementation commit.

## Verification Baseline

At minimum, establish and run the workspace-level commands plus:

```bash
node --test tests/*.test.js
```

Record exact commands actually used; do not claim a gate was verified if it was not executed.

## Evidence

Create:

`docs/12-evidence/WS-001.md`

Evidence must include:

- task/status
- packages covered
- configuration changes
- exact build/typecheck/test commands
- pass/fail results
- regression verification
- known limitations
- commit hash

## Completion

WS-001 can move from READY to DONE only when every acceptance criterion is satisfied and the evidence file is complete.
