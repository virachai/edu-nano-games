# WS-004 — Agent Self-Validation Gate

**Status:** READY  
**Priority:** P1  
**Depends On:** —  
**Owner:** Local Agent  
**Evidence:** docs/12-evidence/WS-004.md

## Objective

Add a repository-level self-validation gate that a local agent can run before final handoff. The gate must detect protocol/state/evidence inconsistencies before the agent stops.

## Context

WS-002 exposed a real lifecycle gap: verification and evidence were produced, but the backlog state was not reconciled. WS-003 added a regression test for the corrected state/evidence contract. WS-004 turns this lesson into an executable pre-handoff validation.

## In Scope

1. Add a small Node.js validation script under `scripts/`, using Node built-ins only.
2. Add a package script named `agent:self-check` that invokes the validator.
3. The validator must:
   - accept an optional task ID argument;
   - read `docs/BACKLOG.md`;
   - when a task ID is supplied, validate that task's backlog row and task/evidence files;
   - verify that the task is not falsely marked `DONE` by the self-check;
   - verify required evidence fields are present: task ID, status, changed files, commands/verification, artifacts/evidence, and blockers/follow-up;
   - verify referenced task/evidence files exist;
   - fail non-zero with a clear diagnostic when a required contract is violated;
   - print a clear `SELF-CHECK: PASS` result when validation succeeds.
4. Add automated tests for the validator, including at least:
   - a passing real repository case;
   - a failing/inconsistent fixture case that proves the validator returns failure.
5. Update `docs/AGENT_RUNBOOK.md` with the self-validation gate only as a minimal protocol addition. Do not redesign the runbook.
6. Create `docs/12-evidence/WS-004.md`.

## Out of Scope

- No agent runner/loop implementation.
- No changes to task lifecycle semantics beyond enforcing existing documented contracts.
- Do not mark WS-002, WS-003, or WS-004 DONE.
- No unrelated refactors.
- Do not modify existing WS-002/WS-003 tests unless required to keep the suite valid.

## Required Verification

Run:

```bash
pnpm test
pnpm agent:self-check -- WS-004
```

If `pnpm` is unavailable in the execution environment, run the equivalent underlying Node commands and record the environment limitation honestly.

## Acceptance Criteria

- `scripts/agent-self-check.mjs` exists and is executable through the package script.
- `pnpm agent:self-check -- WS-004` (or the documented equivalent Node command) returns exit code 0 and prints `SELF-CHECK: PASS`.
- Automated tests prove both success and failure behavior.
- The validator catches the class of lifecycle/evidence inconsistency exposed by WS-002.
- Runbook documents SELF-CHECK between VERIFY and EVIDENCE/HANDOFF.
- Evidence records exact commands, results, changed files, artifacts, and limitations.
- WS-004 remains non-DONE and DWB105 remains the reviewer.

## Constraints

- Prefer Node built-ins; no new dependency unless clearly necessary.
- Keep implementation deterministic and readable.
- Do not infer correctness from agent prose alone; validate repository state.
- Do not silently repair invalid state. The self-check must report failure so the agent can fix it.
- A passing self-check is a gate, not reviewer approval.

## Handoff

Use the standard handoff format from `docs/AGENT_RULES.md` and stop after evidence/handoff.
