# WS-006 — Bounded Loop / Runner Integration

**Status:** READY  
**Priority:** P1  
**Depends On:** WS-005  
**Owner:** Local Agent  
**Evidence:** `docs/12-evidence/WS-006.md`

## Objective

Make the bounded agent loop use the real single-cycle runner as its execution primitive, so there is one canonical implementation for per-invocation locking, timeout handling, logging, and exit-code propagation.

## Scope

1. Update `scripts/agent-loop.sh` so each cycle delegates the actual agent invocation to `scripts/agent-runner.sh`.
2. Preserve the existing loop controls:
   - `--interval`
   - `--duration`
   - `--start-delay`
   - `--log-dir`
   - custom agent command after `--`.
3. Ensure the loop does not duplicate runner responsibilities such as per-run locking, timeout handling, or agent log formatting.
4. Keep loop-level logging for cycle boundaries, sleep decisions, and aggregate exit status.
5. Define how the loop passes its configured log directory to the runner without causing log collisions or lock collisions.
6. Preserve synchronous one-cycle-at-a-time execution.
7. Add focused regression tests for:
   - loop delegates to the runner;
   - custom command arguments are preserved;
   - runner exit status is surfaced at cycle level;
   - no overlapping cycle invocation is introduced.
8. Update `docs/AGENT_LOOP_RUNBOOK.md` to describe the runner-backed architecture and the resulting log/lock responsibilities.
9. Create `docs/12-evidence/WS-006.md` with exact verification results and a standard handoff.

## Constraints

- Execute only this task; do not change product/game logic.
- Do not redesign the READY-task protocol.
- Do not add automatic task claiming, lifecycle promotion, reviewer approval, or parallel agents.
- Do not remove the bounded duration/interval safety model.
- Do not silently change the public CLI without documenting the change.
- Do not delete existing operational logs or evidence.
- Prefer small shell/test changes and existing project conventions.
- The runner remains the canonical single-cycle execution primitive.
- The loop remains the scheduler/bounded repetition layer.
